 8. improvements/08-rvsc1-embench-miscompiles.md   [NEW -- found by item 5]
    The only code defect in this backlog; everything else is documentation.
    edn, qrduino, sglib-combined and wikisort trap under rvsc1 on Spike (exit
    255, load from an address past .bss) while compiling and running correctly
    under rvsc2 and gcc17 from identical sources, so the fault is in synthesis.
    edn's faulting instruction is `lw a2,0(a3)` in jpegdct with a3 = 0x379f0,
    sitting just after a variable-count shift-synthesis loop -- the shape of the
    IRA register-corruption family that NOTRAMP_REGS, the t0/t1 clobbers and
    NORA_REGS/=&yr each addressed for other registers, suggesting that
    enumeration is still incomplete. Not proven; tracing where a3 is written is
    the next step. nsichneu's new timeout is likely related and worth checking
    for a stuck loop. Task file also records a separate latent bug found while
    bisecting: -mshift on rvsc1 ICEs with "unrecognizable insn" on a plain
    reg/reg lshiftrt, so the native shift define_insn stays gated off even when
    TARGET_SHIFT is restored -- harmless for the shipped target, but it breaks
    the define_insn/define_expand sync invariant in CLAUDE.md.
